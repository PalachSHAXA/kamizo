# Isolated E2E Harness Design

## Goal

Run Kamizo's Playwright suites deterministically against the real production Worker code and a disposable local D1 database, without sending requests to or mutating production.

## Constraints

- Do not modify application business code.
- Do not access production services, databases, or Cloudflare remote bindings.
- Do not use long-lived production JWTs or credentials.
- Do not commit or deploy.
- Start the backend and frontend from Playwright `webServer`.
- Give each invocation a unique database and remove it after the run.
- Keep retries bounded and CI-compatible.

## Architecture

Each Playwright phase starts one Node harness process. The harness creates a unique private directory under the operating system temp directory, writes a local-only Wrangler JSON config and `.dev.vars`, initializes D1 from `cloudflare/schema.sql`, runs production runtime migrations plus the declared checked-in migration plan, validates local PRAGMAs against `prod-schema-contract.json`, inserts deterministic fixtures, and starts Wrangler plus Vite as child processes. Signal handlers terminate all tracked children and remove the run directory.

The Worker uses a test-only entrypoint around `cloudflare/src/index.ts`, local D1/KV/R2 bindings, and a stateful local `CONNECTION_MANAGER` Durable Object. The object tracks subscriptions and broadcast events by tenant/channel, validates payloads, rejects tenant mismatches, and exposes harness-only state probes. Its environment is `test`; its JWT secret is generated for the run and exists only in the temporary `.dev.vars` file. No remote binding is enabled. Browser and Worker outbound HTTP are localhost-only and redirect-aware.

The frontend currently hardcodes `https://api.kamizo.uz`. A Playwright fixture intercepts that origin and proxies requests to `http://127.0.0.1:8787`, preserving method, headers, and body. Responses come from the real Worker and D1, not from mocked endpoint payloads. Tests import this fixture instead of `@playwright/test`.

## Data And Authentication

The seed contains one active tenant, one branch, one building, one apartment, request categories, and every role used by the seven suites. Tenant-scoped users share a test-only password; the global super-admin has a separate test-only password. Password hashes are generated by the harness with the same PBKDF2 format consumed by production auth.

Global setup logs each role in once against the local Worker and writes tokens inside the run temp directory identified by `KAMIZO_E2E_RUN_DIR`. Tokens are never reused across runs and are deleted with the database. Login and health checks use bounded retry loops; Playwright retries remain bounded in CI.

## Suite Migration

All seven suites use the isolated fixture. API mutation suites continue asserting real persistence and RBAC. UI suites use the browser proxy. The rentals overflow suite retains its existing frontend development fixtures because it tests layout states, but all network access to the production API origin is still blocked or redirected locally.

The core isolated config runs suites 00-06: isolation/binding probes, API and ordinary UI suites once in desktop Chromium, with the adaptive suite repeated over explicit viewport projects. Separate rental and marketplace configs run suite 07 states without allowing their development fixtures to replace core authenticated roles or each other. Every phase uses the local harness and outbound network guard.

## CI And Failure Handling

`npm run test:e2e:isolated` is the canonical command. CI installs both frontend and backend dependencies before running it. Startup fails if schema initialization, local schema validation, seed insertion, Worker readiness, or Vite readiness exceeds its deadline. Child output is preserved for diagnosis, and failed Playwright tests retain trace/screenshot/video artifacts.

The proxy rejects accidental non-local API fallback. Cleanup is idempotent and runs on normal exit, SIGINT, SIGTERM, startup failure, and Playwright web-server shutdown.

## Verification

- Unit-test deterministic helper behavior where it can fail independently: run-directory ownership, seed SQL generation/escaping, bounded readiness, and process cleanup.
- Run `npm run test:e2e:isolated` locally and report exact passed, failed, and skipped counts by suite/project.
- Run frontend and backend TypeScript checks plus the frontend build.
